S1 领域 · MH.COMMAND

蓝图规划台

Mission, Blueprint & Work

把一个长期使命变成可批准、可施工、可验收的蓝图树，并始终给出唯一、可解释的下一步。

诚实边界

第二层候选蓝图加入 B1/WorkItem、Decision Ledger、Execution Envelope、上下文预览和受戒律约束的下一步。

长期愿景

蓝图规划台的长期愿景

长期形成可缩放的 B∞/T∞ 施工网络，让每次执行、成果、证据和纪元都能沿稳定引用返回总使命。

为什么这样设计

设计理念

蓝图规划台把长期工程的治理状态放在聊天之上：Session 可以结束，Mission、决定和验收边界不能随之消失。它先冻结塔尖，再允许子蓝图和叶任务在已批准边界内生长。

模块只拥有施工意图与任务状态，不直接运行 Agent，也不替戒律授权或替伊甸园验收。Goal、Plan、Todo 只是 Engine 内单次执行的镜像和草稿，不能反向覆盖 Kernel 中的长期事实。

Miracle × Agent Harness

Agent Harness 术语

这些词描述本模块真正拥有或消费的产品对象；它们与底层 Engine 的 Session、Agent Loop 和工具执行保持清晰边界。

Mission（使命）
跨越多次 Session、模型切换和文件变化仍然有效的长期工作单元，保存最终成果、范围、边界、验收与停止条件。
Blueprint（蓝图）
版本化的施工方案；B0 是总蓝图，B1/B2+ 在父层边界内逐层细化，不能用一次对话里的 Plan 代替。
WorkItem（工作项）
由蓝图分解出的可跟踪工作；只有目标、范围、依赖、验收和停止条件完整的叶节点才可进入执行。
Decision Ledger（决定账本）
记录关键选择、被放弃方案、依据和影响范围的长期账本，让后续 Agent 不必重新猜测旧决定。
Execution Envelope（执行信封）
一次 Run 的不可变开工确认单，绑定准确任务、蓝图、戒律、上下文、工具、预算、权限和停止条件。
Next Action（唯一下一步）
由 Kernel 根据权威快照计算并附带理由、阻塞与对象引用的一个推荐动作，不由页面或模型自行猜测。

它拥有的事实

职责

  • 拥有 Mission、Blueprint、WorkItem、Decision 的权威状态与版本关系。
  • 坚持先 B0 总蓝图、再 B1/B2 局部蓝图；只有边界完整的叶任务才进入执行。
  • 把目标、范围、戒律、上下文、工具、预算与停止条件封装为执行信封。

边界先于能力

明确不负责

  • 不直接运行模型、工具或文件操作，也不把聊天中的完成声明当作任务关闭。
  • 不批准适用于自己的戒律；权限判断归戒律，成果质量判断归伊甸园。
  • 不复制会话谱系、物理文件或运行轨迹的原始事实。

进入模块

输入

  • 人类给出的使命种子、边界、最终成果与停止条件。
  • 戒律版本、根系文件投影、智慧之泉来源与伊甸园验收结论。
  • 执行中的决定、阻塞、技术债和冬季候选差异。

离开模块

输出

  • 精确版本的 Mission 与 B0→B∞ Blueprint 树。
  • T0→T∞ WorkItem 树、Decision Ledger、Execution Envelope 与唯一 Next Action。
  • 可供金字塔、世界树、天使议会和观星台引用的稳定 ID。

数据语言

核心对象

  • Mission
  • Blueprint
  • WorkItem
  • Decision
  • ExecutionEnvelope
  • NextAction

缩放而不改事实

层级与 LOD

  • S1 是蓝图规划台；S2 展开使命、蓝图树、任务树、决定账本、执行信封和下一步。
  • B0/B1/B2+ 表示施工意图的逐层分解，T0/T1/T2+ 表示工作的逐层分解，两者不混用。
  • LOD0 看使命、纪元和总进度，LOD1 看蓝图/任务节点，LOD2+ 下钻决定、条件与证据引用。

ProjectEpoch

四季行为

春Spring

建立 Mission，审阅 B0、边界、验收条件与戒律，并由人类冻结准确版本。

夏Summer

按冻结基线拆出可执行叶任务；变更以 Decision 和新版候选记录，不悄悄改基线。

秋Autumn

读取伊甸园的接受或退回结论，只有证据满足完成定义时才关闭 WorkItem。

冬Winter

汇总偏差、技术债与失败决定，提出下一纪元蓝图差异，但不自行激活。

先塔尖，后第二层

下一阶段与验收

先让一个批准后的 B0 长出一个信息完整的 B1 和叶 WorkItem，并将其绑定到一次真实、受限的模型运行。

可检查的验收条件

  • 重启后仍能读取同一 Mission、批准版本、Decision 与叶任务状态。
  • 未批准的蓝图版本不能启动执行，已批准版本不能被静默覆盖。
  • 运行能够证明自己绑定了准确的 Mission、Blueprint、WorkItem 和戒律版本。
