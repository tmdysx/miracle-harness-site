长期成为可像图片一样缩放、折叠、搜索和回溯的执行世界树，覆盖多 Agent 会议与跨纪元谱系。

为什么这样设计

设计理念

世界树把长程工作的情节记忆做成关系图，但不抢夺原始事实：消息和运行事件仍在 Engine Session log，任务状态仍在 COMMAND，世界树只拥有可追溯的 RelationEdge 与谱系投影。

关系采用稳定 ID 和来源事件，而不是标题、路径或画布坐标。这样用户可以把复杂枝叶折叠、缩放或重新布局，同时仍能从成果回到产生它的对话、任务、文件和证据。

Miracle × Agent Harness

Agent Harness 术语

这些词描述本模块真正拥有或消费的产品对象；它们与底层 Engine 的 Session、Agent Loop 和工具执行保持清晰边界。

Session（会话）
Engine 中一段可持久化、可重放的 Agent 交互记录；一个 Mission 可以有多个 Session，但不能依赖其中一个聊天历史充当全部记忆。
RunBinding（运行绑定）
把 Session/Run 与准确 Mission、WorkItem 和 Execution Envelope 连接起来的稳定关系。
RelationEdge（关系边）
记录对话、任务、Agent、输入文件、工具、成果与证据之间关系及其来源事件的领域事实。
LineageNode（谱系节点）
世界树中的可寻址对象投影，可代表主线程、分支、Subagent、Run 或成果，并保留稳定 ID。
Fork / Subagent Lineage（分支谱系）
记录子会话从哪里分出、为哪个任务服务、如何汇报和回到主线的关系，而不是另开无边界主任务。
Conversation Projection（会话投影）
由 append-only Session 事件确定性生成的可搜索、可折叠视图；界面布局本身不是权威历史。

它拥有的事实

职责

  • 投影当前 Mission 的主对话、分支 Session、fork 来源与 Subagent 汇报关系。
  • 建立 Conversation、WorkItem、Run、ExecutionEnvelope、文件、成果和证据之间的稳定 RelationEdge。
  • 支持按时间、任务、Agent、引用和关系路径检索历史。

边界先于能力

明确不负责

  • 不拥有任务状态或关闭决定；这些事实归蓝图规划台。
  • 不改写 append-only Session 事件，也不把可视化布局当作权威关系。
  • 不替代观星台的运行诊断或根系的物理文件索引。

进入模块

输入

  • DSH Session、message、fork、subagent 和 durable event。
  • COMMAND 的 WorkItem/Envelope 引用、ROOT 的 FileRef 与 EDEN 的 ArtifactRef。
  • Agent 会议的上下文选择、模型绑定与交接关系。

离开模块

输出

  • RelationEdge、RunBinding、LineageNode 与可重放 Conversation Projection。
  • 从任意对话节点返回任务、输入、工具、输出、证据和父分支的路径。
  • 供时光胶囊选择上下文、金字塔缩放与全局搜索使用的关系索引。

数据语言

核心对象

  • SessionRef
  • RelationEdge
  • RunBinding
  • LineageNode
  • ConversationProjection
  • SearchResult

缩放而不改事实

层级与 LOD

  • S1 是世界树；S2 展开主线程、分支 Session、Run 绑定、谱系和会话搜索。
  • 关系可从 Mission → Session → Turn/Run → Tool/Artifact 逐层展开，但原始事件仍保存在执行日志。
  • LOD0 看主干和活跃分支，LOD1 看节点/边，LOD2+ 重放原始消息与事件证据。

ProjectEpoch

四季行为

春Spring

从种子或旧胶囊恢复主干，标出继承、废弃和待确认的历史分支。

夏Summer

随着每次对话、fork 和运行追加关系；任何连接都保留来源事件。

秋Autumn

把被验收的成果和决定接回产生它们的对话与任务路径。

冬Winter

折叠低价值枝叶、生成可追溯摘要和冷层索引，但不删除原始谱系。

下一阶段与验收

为现有单模型 Session 建立 append-only RelationEdge，并从界面上的一次消息下钻到绑定的 B0 和运行事件。

可检查的验收条件

  • 每条关系都能指出来源事件和稳定对象 ID，重启后不因标题或布局变化而断裂。
  • 世界树显示的任务状态始终来自 COMMAND，不产生第二份可写状态。
  • 从成果可回溯至对话/运行，从对话可前往输入、输出和证据。
