S1 领域 · MH.ARMORY

众神武库

Tool, Skill, MCP & API Registry

把模型 API、Tool、Skill、MCP 与连接器做成可替换、可测试、最小权限的能力零件，并把凭据留在安全边界内。

诚实边界

当前状态

长期愿景

众神武库的长期愿景

长期形成沙盒式能力市场，允许模型、Agent、Skill、MCP、工具和索引器独立组合、升级、卸载与审计。

为什么这样设计

设计理念

众神武库是能力目录和安全网关，不是工具调用历史。它让模型、API、Tool、Skill 与 MCP 像沙盒零件一样独立组合、升级和撤销，同时把每项能力的来源、版本、Schema、风险和健康状态暴露给治理层。

安全边界采用凭据引用与最小权限：明文密钥只进入操作系统安全存储和受限代理；真正启用能力还要通过戒律预检。工具实际怎样被调用、耗时与结果如何，则由观星台从原始事件投影。

Miracle × Agent Harness

Agent Harness 术语

这些词描述本模块真正拥有或消费的产品对象；它们与底层 Engine 的 Session、Agent Loop 和工具执行保持清晰边界。

Provider / Connector（提供方 / 连接器）
把模型 API、REST、SSE、Webhook 或 WebSocket 服务映射为受控能力的版本化适配器。
ToolProfile（工具档案）
声明工具名称、JSON Schema、执行 Provider、数据访问、网络访问、风险和所需权限的注册记录。
Skill（技能）
可发现、可装配的工作方法与配套资源；登记或阅读 Skill 不等于获得执行其工具的权限。
MCP Connector（MCP 连接器）
登记 MCP Server 的来源、能力、版本、健康和授权范围，使外部工具可替换且可撤销。
CredentialRef（凭据引用）
指向操作系统安全存储中密钥的非明文标识；Renderer、日志、数据库和胶囊不得保存或回显真实密钥。
PolicyBinding（政策绑定）
把某项能力与适用戒律、允许路径、网络范围和批准要求连接起来的治理关系。
Health Check（健康检查）
验证连接、版本、能力、速率和失败降级是否可用的探测结果；可用性不会自动代表本次 Run 已获授权。

它拥有的事实

职责

  • 登记工具 Schema、风险、执行 Provider，Skill 来源/版本，以及 MCP/API 能力和健康状态。
  • 管理 DeepSeek、OpenAI-compatible、Anthropic、Gemini 等模型 Provider 的能力差异和连接测试。
  • 只保存凭据引用与可用性，通过操作系统安全存储和受限代理使用密钥。

边界先于能力

明确不负责

  • 不在 Renderer、日志、仓库或导出文件中保存明文 API Key。
  • 登记能力不等于授权调用；实际权限仍由戒律和执行信封决定。
  • 不拥有工具调用历史；运行事实和错误归观星台。

进入模块

输入

  • Tool JSON Schema、Skill 清单、MCP Server 描述、API 协议和 Provider 元数据。
  • 用户配置的端点、模型、能力声明与操作系统安全存储中的凭据引用。
  • 健康检查、速率限制、版本变化、错误和戒律风险分类。

离开模块

输出

  • ToolSpec、SkillRef、MCPConnector、ModelProvider、CredentialRef 与 HealthCheck。
  • 供 Agent Preset 装配的能力清单、风险标签、失败降级和可撤销绑定。
  • 不含秘密的连接状态与发送前能力/权限摘要。

数据语言

核心对象

  • ToolSpec
  • SkillRef
  • MCPConnector
  • ModelProvider
  • CredentialRef
  • HealthCheck

缩放而不改事实

层级与 LOD

  • S1 是众神武库；S2 展开 Tool、Skill、MCP、Model Provider、HTTP API、CredentialRef 与健康/政策。
  • 能力层级从 Provider/Connector → Capability → Version/Schema → CredentialRef/PolicyBinding 展开。
  • LOD0 看可用性和风险，LOD1 看连接/能力，LOD2+ 看 Schema、版本、测试和权限来源，永不显示明文密钥。

ProjectEpoch

四季行为

春Spring

为新纪元选择最小能力组合，测试连接，确认版本、风险、费用和撤销方式。

夏Summer

监控健康和速率，按执行信封提供能力；错误重绑保留旧会话证据。

秋Autumn

核对实际使用、成本、失败与产出，向伊甸园和观星台提供版本关联。

冬Winter

撤销闲置凭据、升级或淘汰失效组件，保留旧组合清单和兼容/回滚说明。

下一阶段与验收

完成 Provider 能力探测和连接健康检查，让发送前明确显示文本/工具/视觉、上下文、费用与本次权限。

可检查的验收条件

  • 明文凭据只进入操作系统安全存储和受限代理，不出现在 Renderer、日志或仓库。
  • 错误重绑不会改写旧会话、错误或模型来源；撤销后连接立即不可用。
  • 任何能力启用都能指出版本、Schema、风险、适用戒律和健康状态。
